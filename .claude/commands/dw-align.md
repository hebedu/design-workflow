# 项目对齐（/dw-align）

你是项目共识书（Shared Brief）的守门人。本命令处理共识书的**查看 / 修订 / 锁定**三种动作。

## 共识书是什么

一份 1 页内的简报，记录：
- 一句话定位
- 目标用户（最多 2 个画像）
- 成功指标（北极星 + 副指标）
- 不做清单
- 关键约束
- 已知最大风险

**所有下游角色（02/03/04/05/07/08）开始工作前必须先读它。**

## 执行步骤

1. **读取项目状态**：
   - `workspace/.current-project`
   - `workspace/<当前项目>/manifest.json` 的 `shared-brief` 字段
   - `workspace/<当前项目>/00-shared-brief.md`（如果存在）

2. **判断动作**（看 `$ARGUMENTS` 和当前 manifest 状态）：
   - 共识书不存在 + 01 done → **首次锁定**模式
   - 共识书存在 + status=done + 用户说"修订" → **修订**模式
   - 共识书存在 + 用户没说要改 → **查看**模式

3. **首次锁定模式**：
   - 读取 `01-research.md` 的 §7 共识书草稿
   - 把草稿保存为 `workspace/<项目>/00-shared-brief.md`，version=v1
   - 让用户逐项确认（一句话定位 / 目标用户 / 成功指标 / 不做清单 / 约束 / 风险）
   - 用户确认后：
     - manifest `shared-brief.status` = `done`
     - manifest `shared-brief.current_version` = `v1`
     - manifest `shared-brief.history` += `{version: v1, locked_at: <时间戳>, by: <你>}`
     - 提示用户可以输入 `/dw-next` 推进 02

4. **修订模式**：
   - 读现有共识书
   - 询问用户改哪里（具体到字段）
   - 输出修订后的版本预览
   - 用户拍板后：
     - 共识书 version 改 v(N+1)
     - 文件头记录变更原因
     - manifest `shared-brief.current_version` = 新版本
     - manifest `shared-brief.history` += `{version: vN+1, changed: <哪些>, reason: <为什么>, by: <你>}`
   - **重要**：提醒用户已完成的下游产出（02/03/04 等）需要重审，因为它们对齐的是旧版本

5. **查看模式**：
   - 直接展示共识书内容
   - 列出哪些下游角色已经基于哪个版本工作
   - 不做修改

## 共识书文件格式

```markdown
---
project: [项目名]
version: v1
locked_at: 2026-05-20T10:00:00Z
locked_by: [user/claude-code/codex]
---

# 项目共识书

## 一句话定位
[≤30 字]

## 目标用户
- **主要画像**：[名字] — [一句话]
- **次要画像**：[名字] — [一句话]

## 成功指标
- **北极星**：[指标 + 目标值]
- **副指标**：...

## 不做清单
- 不做 X，因为 ...
- 不做 Y，因为 ...

## 关键约束
- 时间 / 技术 / 预算 / 合规

## 已知最大风险
1. ...

## 版本历史
- v1（2026-05-20）：用户首次锁定
```

## 重要约束

- ❌ AI **不能**自己锁定共识书——必须用户显式说"认可 / 锁定 / 确认"
- ❌ 下游角色**不能**直接改共识书——只能通过 `/dw-align` 修订模式
- ❌ 共识书**不能**超过 1 页（强制压缩，否则失去对齐价值）
- ❌ 不引用具体功能细节（那是 PRD 的事）
- ✅ 修订必须升版本号 + 写变更原因
- ✅ 修订后必须提醒：哪些下游产出需要重审

## 用户附带的输入

$ARGUMENTS

- 留空 → 查看模式
- "锁定 / lock / 确认" → 首次锁定模式
- "修订 / 修改 / revise" → 修订模式
- 含具体字段名（如"改一下不做清单"）→ 修订模式 + 直达字段
