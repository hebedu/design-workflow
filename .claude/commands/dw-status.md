# 查看项目状态

请展示当前项目的完整状态。

## 执行步骤

1. 读取 `workspace/.current-project` 获取当前项目名（如不存在，提示用户先运行 `/dw-init`）
2. 读取 `workspace/<当前项目>/manifest.json`
3. 用清晰的表格展示状态：

```
项目：[项目名]    创建于：[日期]    版本：[版本号]

┌──────────────────────┬──────────┬─────────────────┬──────────────┐
│ 角色 / 阶段            │ 状态      │ 产出文件          │ 完成方       │
├──────────────────────┼──────────┼─────────────────┼──────────────┤
│ 01 研究助理            │ ✅ done  │ 01-research.md   │ claude-code │
│ 02 产品助理            │ 🔄 in    │ -                │ -            │
│ 03 交互助理            │ ⏸ pending│ -                │ -            │
│ 04-A 风格探索          │ ⏸ pending│ -                │ -            │
│ 04-B 高保真            │ ⏸ pending│ -                │ -            │
│ 04-C 前端工程包         │ ⏸ pending│ -                │ -            │
│ 05 评审员              │ ⏸ pending│ -                │ -            │
│ 06-A 走查清单          │ ⏸ pending│ -                │ -            │
│ 06-B 走查报告          │ ⏸ pending│ -                │ -            │
│ 07 上线运营（可选）     │ ➖ n/a    │ -                │ -            │
└──────────────────────┴──────────┴─────────────────┴──────────────┘
```

4. 根据当前进度，建议下一步该调用哪个命令：
   - 如果 01 done，02 pending → 建议 `/dw-pm`
   - 如果 02 done，03 pending → 建议 `/dw-ux`
   - 如果 05 done，06 pending → 建议 `/dw-uat-list`
   - 如果 05 done 且需求需要对外传播 / 用户教育 / 增长 → 建议 `/dw-launch`（可选 07）
   - 等等

> 07 launch-ops 默认 `n/a`（不适用）。它不在主链路推进上，只在用户显式触发后变成 in_progress / done。

## 用户输入

$ARGUMENTS

如果用户附带了"切换 [项目名]"，则更新 `workspace/.current-project` 文件并切换。
