# 进化命令（dw-evolve）

把 `learning/` 目录积累的反馈合并回 `workflow/roles/0X-*.md`，让角色脚本本体越来越强。

## 何时运行

- 每完成 5-10 个项目跑一次
- 看到 post-commit hook 提示「已累积 N 条 diff insights」时
- 想给某个角色"升级"前手动触发

## 执行步骤

1. **确认范围**：
   - 问用户：要合并所有角色，还是指定某个角色（如 `02-pm`）？
   - `$ARGUMENTS` 如果有内容，作为目标角色 ID

2. **读取学习数据**：
   - 读 `learning/corrections.md`（所有对话修正记录）
   - 读 `learning/diff-insights.md`（所有 diff 模式记录）
   - 读 `learning/role-patches/<目标角色>.patch.md`（累积的可执行补丁）

3. **去重 + 归类**：把所有信号按角色聚合，识别：
   - 高频规则（出现 ≥ 3 次的修正模式）→ 必须合并
   - 中频规则（2 次）→ 与用户确认后合并
   - 低频规则（1 次）→ 保留在 patch 中暂不合并
   - 矛盾规则 → 列出请用户裁决

4. **生成合并方案**（不直接改文件）：
   - 对每个目标角色，输出一份合并预览：
     - 原始角色脚本中要修改的位置（具体行 / 章节）
     - 新增的规则
     - 删除/修改的旧规则
     - 影响范围预估
   - 让用户审阅，确认才合并

5. **备份原始脚本**：
   - 把 `workflow/roles/<角色>.md` 复制到 `draft/evolve-backup/YYYY-MM-DD/<角色>.md`
   - 这是回滚的唯一路径，不要省略

6. **执行合并**：
   - 用户确认后，用 Edit 工具修改角色脚本本体
   - 把合并掉的规则从 `role-patches/<角色>.patch.md` 中移除
   - 已合并的 corrections 在 `corrections.md` 里标记 `merged_at: <日期>`

7. **写入 changelog**：
   - 追加到 `learning/prompt-changelog.md`：
     - 角色名 + 新版本号（角色脚本顶部如有版本号则递增）
     - 合并来源数量
     - 主要变更摘要
     - 备份路径

8. **结束语**：告诉用户：
   - 合并了哪些角色、共 N 条规则
   - 备份位置（万一要回滚）
   - 建议跑一次小项目验证新角色脚本

## 用户附带的输入

$ARGUMENTS

可以指定单个角色（如 `02-pm`）或留空（合并所有有补丁的角色）。

## 重要约束

- ❌ 不要在用户确认前修改角色脚本本体
- ❌ 不要合并低频或矛盾的规则
- ❌ 不要丢掉项目特异性的 patch（只合并通用规则）
- ✅ 备份永远先做
- ✅ 合并后给用户清单，可立刻回滚
- ✅ 矛盾规则要让用户裁决，AI 不擅自决定

## 回滚方式

如果合并后发现新版角色脚本表现变差：

```bash
cp draft/evolve-backup/YYYY-MM-DD/0X-xxx.md workflow/roles/0X-xxx.md
```

然后告诉用户回滚完成，被回滚的合并需要重新评估。
