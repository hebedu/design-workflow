## TL;DR
需求成立：该作品集应以大胆插画旅程建立记忆点，同时让招聘方快速看清 Bingxin Du 的角色、价值与 AI 产品设计能力。

## 0. 需求成立性判断
- **结论**：成立
- **理由**：目标岗位明确为产品设计师 / UX 设计师 / 产品经理；内容资产包含 8 个项目、个人介绍、发展时间线；差异化方向明确为 C 端体验、产品思维、全栈 AI 设计与个人化小熊猫视觉 IP。
- **必须先确认的问题**：
  - [ ] 8 个项目的真实标题、角色、价值点、结果数据。
  - [ ] 公司项目是否需要脱敏或密码保护。
  - [ ] 目标市场更偏国内、海外、大厂、创业公司还是 AI 公司。

## 1. 需求拆解
| 层级 | 内容 | 验收点 |
|------|------|--------|
| 主需求 | 建立双语响应式作品集网站 | 30 秒内看懂姓名、目标岗位、主推项目、差异化能力 |
| 子需求 1 | 大胆有趣首页 | 使用 Design Journey 插画场景与小熊猫阅读 IP |
| 子需求 2 | 8 个项目快速识别 | 每张项目卡默认展示 Role 与 Value |
| 子需求 3 | 主推项目突出 | HuKe / Zencard / SRE Agent 作为首屏主线节点 |
| 子需求 4 | AI 设计特色 | 展示 AI-native Product 与 Full-stack AI Workflow |
| 子需求 5 | 双语与响应式 | 支持 CN / EN、桌面与移动端浏览 |

## 2. 假设与风险
- **关键假设**：
  - 访客主要是招聘方、设计负责人、产品负责人、HR。
  - “有趣”是加分项，但不应压过专业判断。
  - 当前项目内容可先 mock，后续替换真实数据。
- **风险**：
  - 插画 IP 过强会显得幼态。
  - 整张图切为背景会降低可维护性和双语能力。
  - 公司项目如果未脱敏，可能存在保密风险。

## 3. 竞品分析
| 参考 | 核心功能 | 亮点 | 短板 |
|------|---------|------|------|
| Ben Shih Portfolio | 工作项目 + 独立产品 | Designer/Builder 定位清晰 | 视觉更克制，个性插画弱 |
| UXfolio Case Study | 标准项目叙事 | 清晰展示角色、过程、结果 | 模板感强 |
| 设计师互动作品集案例 | 强视觉首页与动效 | 容易被记住 | 容易牺牲信息效率 |

**对我们的启示**：
- 首页必须同时有记忆点和扫描效率。
- 项目卡片应在点击前展示 Role / Value。
- 小熊猫适合作为引导角色，不应成为唯一主角。

## 4. 用户痛点 Top 5
1. **招聘方时间少** — 场景：快速筛选作品集 / 频率：高 / 影响：首屏不清会被关闭。
2. **看不清候选人贡献** — 场景：公司项目多人协作 / 频率：高 / 影响：无法判断能力边界。
3. **作品集只好看但不产品化** — 场景：只有 mockup / 频率：中高 / 影响：不利于产品设计与 PM 岗位。
4. **AI 能力表达泛泛** — 场景：只写 AI 标签 / 频率：中 / 影响：无法证明 AI 产品流程能力。
5. **移动端体验弱** — 场景：手机打开链接 / 频率：中 / 影响：损害第一印象。

## 5. 机会点
- 用 “Design Journey” 作为首页主概念。
- 将 3 个主推项目放入旅程节点，并默认显示角色和价值。
- 用小熊猫阅读形象表达学习、探索与个人温度。
- 用 AI Design Flow 模块系统化表达全栈 AI 设计能力。
