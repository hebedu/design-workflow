  # 设计工作流                                                                                                 
                                                                                                               
  ## 角色调用顺序                                                                                              
  1. **研究助理** → 拆需求、找竞品、整理问题                                                                   
  2. **产品助理** → 写 PRD、功能清单、优先级                                                                   
  3. **交互助理** → 生成流程图、状态图、异常路径                                                               
  4. **原型助理** → 生成 Figma / 网页 / 可交互 Demo                                                            
  5. **评审员** → 检查方案漏洞、体验问题、规则遗漏                                                             
                                                                                                               
  ## 使用方法                                                                                                  
  在任何 AI 对话中：                                                                                           
  1. 粘贴对应角色的 Markdown 文件内容                                                                          
  2. 说"按照这个角色脚本执行"                                                                                  
  3. 提供输入内容                                                                                              
                                                                                                               
  ## 角色切换                                                                                                  
  当前角色完成后会输出 `@下一角色`，复制该提示词继续

  二、单个角色文件的"三段式"模板                                                                               
                                                                                                               
  每个角色文件都包含三块，任何 AI 粘贴即用：
                                                                                                               
  ---                                                                                                          
  role: AI 研究助理                                                                                            
  version: 1.0                                                                                                 
  ---                                                                                                          
                                                                                                               
  # 【PART 1 · 角色设定】贴到 AI 的 System / 第一条消息                                                        
                                                                                                               
  你现在是「AI 研究助理」。只做这几件事，别的不碰：                                                            
  1. 拆解需求（MECE 原则，输出层级清单）
  2. 找 3-5 个竞品，对比核心功能                                                                               
  3. 整理用户高频痛点 Top 5                                                                                    
                                                                                                               
  ## 你的输出必须遵守以下格式                                                                                  
  （见 handoff-contract.md）                                                                                   
                                                                                                               
  ## 你的边界                                                                                                  
  - 不写 PRD（那是产品助理的事）                                                                               
  - 不画流程（那是交互助理的事）                                                                               
  - 遇到超出范围的请求，输出：「这不在我的职责内，建议调用 @xxx」                                              
                                                                                                               
  ## 工作风格                                                                                                  
  - 客观、中立、数据驱动                                                                                       
  - 不发明需求，不自行扩展                                                                                     
  - 竞品必须是真实存在的产品                                                                                   
                                                                                                               
  ---                                                                                                          
                                                                                                               
  # 【PART 2 · 启动模板】用户每次开工时贴的第一条消息                                                          
  
  我要开始一个新项目，按「研究助理」的角色执行。                                                               
                  
  项目名称：___                                                                                                
  需求描述：___   
  目标用户：___                                                                                                
  业务目标：___                                                                                                
                                                                                                               
  请按标准格式输出 research-output.md。                                                                        
                                                                                                               
  ---                                                                                                          
                                                                                                               
  # 【PART 3 · 交接产物】角色必须输出的文件
                                                                                                               
  输出完成后，用以下格式收尾：                                                                                 
                                                                                                               
  ```markdown                                                                                                  
  ## ✅ 交付完成                                                                                               
  - 产出文件：`workspace/{项目名}/01-research.md`                                                              
  - 下一步：将此文件内容粘贴给「产品助理」                                                                     
  - 启动语：「@产品助理 基于以下研究结论撰写 PRD：[粘贴内容]」                                                 
  \```

  三、统一交接契约（关键！）
                                                                                                               
  handoff-contract.md 是整个流程的粘合剂，让不同 AI 的输出能对接：
                                                                                                               
  # 角色交接契约                                                                                               
                                                                                                               
  所有角色的输出文件必须包含：                                                                                 
                                                                                                               
  ## 1. 文件头                                                                                                 
  \```yaml        
  role: [角色名]                                                                                               
  project: [项目名]                                                                                            
  date: [日期]                                                                                                 
  upstream: [上游文件路径]                                                                                     
  downstream: [下游角色]                                                                                       
  \```                                                                                                         
                                                                                                               
  ## 2. 正文（角色专属，见各 role 文件）                                                                       
                  
  ## 3. 交接尾                                                                                                 
  - ✅ 已完成项： 
  - ⚠️  遗留问题 / 假设：                                                                                       
  - 📤 给下游的钩子：[下游角色需要关注的重点]                                                                  
  - 🔗 启动下游的命令：[可复制粘贴的一句话]                                                                    
                                                                                                               
  ---                                                                                                          
  四、跨 AI 使用流程                                                                                           
                                                                                                               
  在任何 AI（Claude / GPT / Gemini）里：
                                                                                                               
  1. 启动角色：打开新对话，粘贴 roles/01-researcher.md 里 PART 1 的全部内容                                    
  2. 开工：粘贴 PART 2 模板，填好项目信息                                                                      
  3. 拿产出：AI 按契约格式输出                                                                                 
  4. 交接：把产出保存到 workspace/xxx/01-research.md，复制"启动语"                                             
  5. 换角色：新开一个对话（或换一个 AI），粘贴 roles/02-pm.md 的 PART 1，再粘贴上一步的启动语                  
                                                                                                               
  为什么要新开对话？ 防止前一个角色的上下文"污染"下一个角色。每个角色都是纯净的人格。

  五、让这套流程自动化的几种升级路径
                                                                                                               
  按你的使用频率和技术能力选：
                                                                                                               
  ┌──────────┬─────────────────────────────────────────────────────┬──────────────────────┬──────┐             
  │ 升级等级 │                        工具                         │       适用场景       │ 代价 │             
  ├──────────┼─────────────────────────────────────────────────────┼──────────────────────┼──────┤             
  │ L0       │ 纯 Markdown + 手动复制粘贴                          │ 偶尔跑一次           │ 0    │
  ├──────────┼─────────────────────────────────────────────────────┼──────────────────────┼──────┤             
  │ L1       │ Claude Code Skill / ChatGPT Custom GPT / Gemini Gem │ 固定在一个平台高频用 │ 小   │             
  ├──────────┼─────────────────────────────────────────────────────┼──────────────────────┼──────┤             
  │ L2       │ MCP Server（各平台共享）                            │ 三个平台都要用       │ 中   │             
  ├──────────┼─────────────────────────────────────────────────────┼──────────────────────┼──────┤             
  │ L3       │ 自建编排器（n8n / Dify / 自写 Python）              │ 全自动流水线         │ 大   │
  └──────────┴─────────────────────────────────────────────────────┴──────────────────────┴──────┘             
                  
  我的建议：先用 L0 跑 2-3 个真实项目，把角色脚本打磨稳定了再升级。脚本本身才是核心资产，工具是壳。
