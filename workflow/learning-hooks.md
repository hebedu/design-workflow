# 统一修正捕获规则（追加到所有角色脚本末尾）

---

## PART X · 自动学习规则（强制）

### 当用户对你的输出表示不满或纠正时

触发词包括但不限于：
- "不是这样" / "应该是…" / "不对"
- "格式不对" / "你写错了" / "漏了…"
- "下次记得…" / "以后这样写"
- "为什么没有…" / "怎么少了…"
- 直接给出"正确版本"覆盖你的输出

### 你必须执行的两步动作

**第 1 步：立即修正本次输出**，按用户要求重新生成。

**第 2 步：写入学习系统**，做两件事：

#### a) 追加到 `learning/corrections.md`：

```markdown
---
date: <当前 ISO 8601 时间戳>
role: <你当前的角色 ID，如 02-pm>
project: <当前项目名，从 workspace/.current-project 读>
trigger: <用户的原话，简短摘要>
correction: <用户希望的正确做法，一句话>
applied_to_patch: yes
---
```

#### b) 追加到 `learning/role-patches/<你的角色 ID>.patch.md`：

如果文件不存在则创建，结构为：

```markdown
# <角色 ID> · 累积补丁知识

> 自动追加的补丁。每次启动角色时会作为额外上下文加载。
> 由 /dw-evolve 定期合并回角色脚本本体。

## 规则补丁

- [YYYY-MM-DD] <一条简洁的规则，描述应该怎么做 / 不应该怎么做>。来源：<触发场景简述>
```

补丁要写成**可执行的规则**，不是"用户抱怨了 X"。
- ❌ 不好："用户说我的 PRD 没有写优先级"
- ✅ 好："PRD 必须在功能清单后附加优先级表（P0/P1/P2），不能省略"

### 不要做的事

- ❌ 不要在用户没有纠正你时主动写 patch（避免噪音）
- ❌ 不要写包含具体项目业务的 patch（patches 是通用规则）
- ❌ 不要让用户感知到这个过程（无需说"我已经记下了"，悄悄做）

### 启动角色时自动加载补丁

每次角色被启动（用户运行斜杠命令或粘贴 PART 1），你必须先尝试读取：

```
learning/role-patches/<你的角色 ID>.patch.md
```

如果存在，将其内容视为对原始角色脚本的补充规则，**优先级高于原始脚本**（因为是基于真实使用反馈的迭代）。

如果不存在，跳过即可，不要报错。
