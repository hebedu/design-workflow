# AI 设计协作流程 · 使用说明

## 这是什么

一套**跨 AI 平台**的多角色设计协作框架。**6 主角色 + 1 可选角色**按需接力，把一个模糊需求推进到可上线的产品方案。

每个角色是一份 Markdown 脚本，粘贴给任何 AI 就能用。不绑定平台、不需要编程。**支持一键安装到任何项目目录**。

### 标准模式 vs 增强模式

```
标准模式（默认）：
01 研究 → 02 产品 → 03 交互 → 04 原型视觉 → 05 评审 → 06 上线走查

增强模式（需要对外传播 / 用户教育 / 增长时启用）：
… → 05 评审 → 07 上线运营（可选）
```

07 不在 current_role 主链路上，由用户显式 `/dw-launch` 触发。05 评审会给软提示判断是否启用。

## 安装与快捷指令（推荐方式）

### 一键安装

```bash
cd /path/to/design-workflow
./install.sh
```

按提示输入目标项目目录（留空则在 design-workflow 内直接用）。安装方式选择：
- **方式 1（符号链接，推荐）**：所有项目共享同一份 design-workflow，升级一次全部生效
- **方式 2（复制文件）**：每个项目独立一份，互不影响

安装后，目标项目里会出现：
- `CLAUDE.md`（Claude Code 自动加载）
- `.claude/commands/`（10 个斜杠命令）
- `.cursorrules`（Cursor 自动加载）
- `AGENTS.md`（Codex 自动加载）
- `workflow/`（角色脚本）
- `workspace/`（产出目录）

### Claude Code 中的斜杠命令

打开装好的项目，直接输入：

| 命令 | 作用 |
|------|------|
| `/dw-init [项目名]` | 初始化新项目 |
| `/dw-status` | 查看当前进度 |
| `/dw-research` | 启动 01 研究助理 |
| `/dw-pm` | 启动 02 产品助理 |
| `/dw-ux` | 启动 03 交互助理 |
| `/dw-style` | 启动 04 阶段 1（风格探索） |
| `/dw-hifi` | 启动 04 阶段 2（高保真单文件原型） |
| `/dw-package` | 启动 04 阶段 3（前端工程包，需 05 评审通过） ★ |
| `/dw-review` | 启动 05 评审员 |
| `/dw-uat-list` | 启动 06 阶段 1（走查清单） |
| `/dw-uat-report` | 启动 06 阶段 2（走查报告） |
| `/dw-launch` | 启动 07 上线运营助手（可选）★ |
| `/dw-evolve` | 把累积的学习补丁合并回角色脚本本体 ★ |

每个命令会自动：
1. 读取对应角色脚本
2. 检查项目状态
3. 做接收体检
4. 执行角色工作
5. 保存产出到 `workspace/<当前项目>/`
6. 更新 `manifest.json`
7. 提示下一步

### Codex / Cursor 用户

- **Codex**：推到 GitHub 后 Codex 拉取即可，自动读取 `AGENTS.md`（无需手动粘贴）
- **Cursor**：直接打开装好的项目，自动读取 `.cursorrules`

两者都能读写 `workspace/` 共享目录，与 Claude Code 互通。

### 网页版 AI（GPT / DeepSeek / Gemini）

不能直接用斜杠命令，但可以：
1. 打开 `workflow/roles/0X-xxx.md`，复制 PART 1 粘贴到对话
2. 复制 PART 2 启动模板，填好后粘贴
3. AI 输出后，手动保存到本地 `workspace/<项目>/0X-xxx.md`
4. 手动更新 `manifest.json`

## 共享 workspace 工作流

所有 AI（CC / Codex / Cursor / 网页版）共享同一个 `workspace/` 目录：

```
workspace/
├── .current-project              ← 一行文本，记当前项目名
└── 2026-05-18-我的项目/
    ├── manifest.json             ← 所有 AI 都读写这个文件
    ├── 01-research.md            ← 01 研究助理产出
    ├── 02-prd.md                 ← 02 产品助理产出
    ├── 03-interaction.md
    ├── 04-style-options.md       ← 04 阶段 1
    ├── 04-style-A.html
    ├── 04-style-B.html
    ├── 04-style-C.html
    ├── 04-prototype-hifi.md      ← 04 阶段 2（单文件原型）
    ├── 04-prototype.html
    ├── 05-review.md
    ├── frontend/                 ← 04 阶段 3（规范前端工程包，评审通过后产出）
    │   ├── package.json
    │   ├── README.md
    │   └── src/...
    ├── uat-checklist.md          ← 06 阶段 1
    └── uat-report.md             ← 06 阶段 2
```

### 三种共享场景

| 场景 | 共享方式 | 说明 |
|------|---------|------|
| **同一台机器**（CC + Cursor） | 天然共享 | 打开同一个目录，workspace 就是同一个，零配置 |
| **跨平台**（CC 本地 + Codex 云端） | **git 同步** | 写完 commit + push，Codex 拉取后继续 |
| **跨设备**（两台 Mac） | iCloud 或 git | 把 repo 放在 iCloud 里自动同步，或通过 git |

### 跨平台协作流程（CC ↔ Codex）

```
1. 你在 CC 跑 /dw-research
   ↓ CC 把产出写到 workspace/项目/01-research.md
   ↓ 更新 manifest.json: 01-research.status=done, by=claude-code
   ↓ 你 git add workspace/ && git commit && git push

2. 你在 Codex 拉取最新代码
   ↓ Codex 读 manifest.json 看到 01=done
   ↓ 你说 "继续做 04 高保真"
   ↓ Codex 自动读 03-interaction.md，做 04 阶段 1+2
   ↓ Codex 写产出到 workspace/项目/
   ↓ Codex 提交 git push

3. 你在 CC 本地 git pull
   ↓ 看到 04 已完成
   ↓ /dw-review 启动评审
```

**关键**：manifest.json 是协调中心，每个 AI 完成后更新它，下一个 AI 拉取后能立刻知道做到哪了。

### 典型用法（混用 AI 平台）

- 用 ChatGPT 网页版做 01 研究（联网搜竞品方便）→ 手动保存到 `workspace/`
- 用 Claude Code 做 02 PRD（`/dw-pm`，自动读 01 + 自动保存）
- 用 Codex 做 04 高保真（产出代码质量高，自动写 HTML 到 `workspace/`）
- 用 Claude 网页版做 05 评审（多模态能看 HTML 截图）

### git 仓库设置

`workspace/` 默认**不被 .gitignore**，会推到 GitHub。这样 Codex / 其他设备能拉取到。

如果你不想把项目产出推到 GitHub（纯本地使用），编辑 `.gitignore`：

```
workspace/
```

但这样 Codex 就拿不到产出了。

## 平台兼容性（重要）

| 角色 | 产出形式 | 可用平台 | 说明 |
|------|---------|---------|------|
| 01 研究助理 | Markdown | **任何 AI** | Claude / GPT / Gemini / DeepSeek / 通义 / Kimi 等 |
| 02 产品助理 | Markdown | **任何 AI** | 同上 |
| 03 交互助理 | Markdown | **任何 AI** | 同上 |
| 04 原型视觉助理 | **Markdown + HTML** | **仅限代码型 AI** ⚠️ | 见下方说明 |
| 05 评审员 | Markdown | **任何 AI** | 同上 |
| 06 上线走查员 | Markdown | **任何 AI** | 同上 |

### ⚠️ 04 原型视觉助理的平台限制

04 需要**生成可运行的 HTML 文件**（阶段 1 静态预览 + 阶段 2 完整交互原型），因此只能用于**支持代码生成和文件输出**的 AI 工具：

| 推荐平台 | 说明 |
|---------|------|
| **Claude Code**（CC） | Anthropic 官方 CLI / IDE，可直接写文件到本地 |
| **Cursor** | AI IDE，可直接生成 HTML 文件 |
| **v0.dev** | Vercel 的 UI 生成工具，适合阶段 1 风格预览 |
| **Lovable** | AI 全栈生成，适合阶段 2 完整原型 |
| **Bolt.new** | 在线 AI 开发环境 |
| **Codex** | OpenAI 代码生成 |
| **Antigravity** | AI 原型工具 |

**不适合 04 的平台**：
- ❌ ChatGPT 网页版（能写代码但不能直接输出文件）
- ❌ Claude.ai 网页版（同上，除非用 Artifacts）
- ❌ Gemini 网页版（同上）
- ❌ 通义 / Kimi / DeepSeek 网页版

> 如果你只有网页版 AI，04 的阶段 1 可以让 AI 输出代码块，你手动保存为 .html 文件。阶段 2 建议切到代码型 AI。

## 快速上手（5 分钟）

### 第一次用？跑一遍骨架轮

1. 打开任意 AI，新对话
2. 复制 `roles/01-researcher.md` 的 **PART 1** 全文粘贴
3. 复制 **PART 2 · 场景 S（骨架模式）** 的启动模板，填好项目信息
4. AI 输出骨架版研究报告，保存到 `workspace/日期-项目名/01-research.md`
5. 依次对 02 → 03 → 04 → 05 重复（每次新开对话）
6. 1 小时内看到端到端的骨架方案

### 日常使用

1. 确定要调用哪个角色（看下方"场景速查表"）
2. 打开对应 AI 平台，新对话
3. 粘贴角色文件的 **PART 1**（角色设定）
4. 粘贴 **PART 2** 中对应场景的启动模板
5. 保存产出到 `workspace/` 对应文件
6. 下一棒

## 每个角色怎么用

### 01 研究助理
**做什么**：判断需求是否成立 → 构建用户画像 → 梳理使用场景 → 绘制用户旅程 → 竞品分析 → 痛点整理

**操作**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 启动模板，填好项目信息
3. 保存产出为 `01-research.md`

**平台**：任何 AI（推荐 ChatGPT，联网搜竞品方便）

---

### 02 产品助理
**做什么**：接收体检 → 写 PRD → 功能清单（基于画像的用户故事）→ 优先级排序

**操作**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 0 + PART 2（把 01 的产出作为输入）
3. 保存产出为 `02-prd.md`

**平台**：任何 AI（推荐 Claude，长文本结构化输出稳）

---

### 03 交互助理
**做什么**：接收体检 → 主流程设计 → 状态机 → 异常路径 → 交互规则

**操作**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 0 + PART 2（把 02 的产出作为输入）
3. 保存产出为 `03-interaction.md`

**平台**：任何 AI

---

### 04 原型视觉助理 ⚠️ 需要代码型 AI
**做什么**：接收体检 → 风格探索（3 选 1）→ 高保真 HTML → 前端工程包（可选）

**操作（阶段 1+2 两次对话，阶段 3 可选第三次）**：

**第 1 次（阶段 1 风格探索）**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 · 场景 A1（把 03 的产出作为输入）
3. AI 输出 `04-style-options.md` + 3 个 HTML 预览文件
4. 在浏览器打开 3 个 HTML，选一个你喜欢的风格

**第 2 次（阶段 2 高保真）**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 · 场景 A2（告诉 AI 你选了哪个风格 + 粘贴上游产出）
3. AI 输出 `04-prototype-hifi.md` + `04-prototype.html`
4. 在浏览器打开 HTML，体验完整交互

**平台**：Claude Code / Cursor / v0 / Lovable / Bolt.new

---

### 05 评审员
**做什么**：戴 4 顶帽子（研究/产品/交互/原型视觉）轮流审查 → 综合问题清单 → 回炉任务单

**操作**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 · 场景 A（把 01-04 所有产出作为输入）
3. 保存产出为 `05-review.md`
4. 按回炉任务单分发给对应角色修改

**平台**：任何 AI（推荐 Claude，长文本 + 多视角分析稳）

---

### 06 上线走查员
**做什么**：生成走查清单 → 你去线上跑 → 整理走查报告 → 回炉清单给开发

**操作（两次对话）**：

**第 1 次（出清单）**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 · 场景 A1（把 PRD + 交互规格作为输入）
3. 保存产出为 `uat-checklist.md`
4. 拿清单去线上跑，标记 ✅/⚠️/❌/❓

**第 2 次（出报告）**：
1. 新对话，粘贴 PART 1
2. 粘贴 PART 2 · 场景 A2（把标记后的清单粘贴回来）
3. 保存产出为 `uat-report.md`
4. 把回炉清单分发给开发 / PM

**平台**：任何 AI

## 三种使用模式

### 模式 1：全链路
01 → 02 → 03 → 04（阶段 1+2，两次对话）→ 05 → 04 阶段 3（可选，需 05 通过）→ 06

适合：从模糊需求开始的新项目

### 模式 2：单点调用
只用某一个角色，按 PART 2 · 场景 B 提供最小输入。

适合：已有部分产出，只需要某一环

### 模式 3：骨架先行
所有角色用场景 S（5 分钟版），先全链路跑通再精修。

适合：想快速验证方向对不对

## 反瀑布机制

### 骨架先行
每个角色都支持「场景 S」骨架模式。1 小时跑完全链路骨架，发现方向错误的成本从 N 天降到 1 小时。

### 接收体检
02/03/04 拿到上游产出后先做 30 秒体检（PART 0），发现问题立刻打回，不浪费时间做在烂输入上。

## 自动学习系统 ★

这套流程会**越用越聪明**。你正常工作就是在训练它。

### 两个信号源（全自动）

| 信号 | 触发 | 捕获什么 |
|------|------|---------|
| 对话修正 | 你说"不对"、"应该是…"、"漏了…" | AI 自动记下规则到 `learning/role-patches/<角色>.patch.md` |
| Git Diff | 你修改 AI 输出后 commit | post-commit hook 自动分析改动模式到 `learning/diff-insights.md` |

### 下次启动角色时

`/dw-research` 等命令会自动读取 `learning/role-patches/<角色>.patch.md`，作为对原始脚本的补充规则加载。角色输出质量随使用次数提升。

### 定期合并（半自动）

每完成 5-10 个项目后，跑一次 `/dw-evolve`：
- AI 分析所有累积的补丁
- 列出合并方案给你审阅
- 确认后把高频规则合并回角色脚本本体
- 原脚本自动备份到 `draft/evolve-backup/`，可回滚

### 你不需要做什么

- ❌ 手写反馈
- ❌ 评分打标签
- ❌ 维护 learning/ 目录

详见 `learning/README.md`。

## 常见问题

### AI 不按脚本输出怎么办？
在对话里追加一句：「请严格按 handoff-contract.md 的格式重新输出，包含文件头 + 正文 + 交接尾。」

### 04 的 HTML 太长，AI 输出被截断？
让 AI 分段输出：「请先输出 HTML 的 head + CSS 部分，我确认后再输出 body 部分。」

### 一个角色的产出太长，下一个角色放不下？
只粘贴 TL;DR + 关键章节（如功能清单、主流程），在启动模板里注明「以下是精简版，完整版见附件」。

### 想跳过某个角色？
可以。每个角色都支持独立调用（场景 B），缺失的上游信息会在「假设与遗留」里标出。

### 多人协作怎么用？
每个人负责不同角色，产出文件放在共享目录（如 iCloud / Google Drive / Git）。交接通过文件，不依赖 AI 对话记忆。
